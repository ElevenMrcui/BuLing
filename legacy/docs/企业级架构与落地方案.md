# 不令 · 企业级架构与落地方案 v1

> 从产品原型阶段迈向企业级私有化交付的**技术方案定稿**。本文是 design-first 纪律下的"设计"，评审通过后配套的最小可跑骨架（`apps/api` + `apps/web` + `packages/shared` + `prisma` + `infra`）为其第一个可编译切片。

## 0. 决策摘要

| 维度 | 结论 |
|---|---|
| 技术栈 | **Node.js 22 + TypeScript**：NestJS（Fastify adapter）做 API，Next.js 14 App Router 承接现有前端原型；单一语言全栈、AI SDK 生态最全 |
| 交付形态 | **私有化部署优先**（信创 / 数据不出内网），SaaS 多租户为 R3 抽象扩展点，非本次范围 |
| 数据平面 | PostgreSQL 16（业务）+ Redis 7（缓存 / 队列 / 实时通道 pub-sub） |
| 编排 | BullMQ（Agent 任务队列）+ SSE（协作时间线推送，避开 WS 私有化环境常见反代问题） |
| 部署 | 本地 Docker Compose；生产 Kubernetes（Helm chart R2 交付），单节点私有化用 systemd + Compose 亦可 |
| 观测 | OpenTelemetry Traces + Prometheus Metrics + Loki Logs |
| 硬约束 | **评审红线不可自动化**（写进代码约束，非仅文档约定） · 三层机制功能名统一 · 主题令牌合规 · 密钥不落库明文 |

## 1. 目标与非目标

### 1.1 目标

1. **把原型交互变成真实可运行系统**：Agent / 任务 / 文档 / 模型接入的 CRUD 与状态机全部落到 DB。
2. **让三层机制在服务端有真实实现**（不是前端假动画）：自主认领机制的意愿累积、临时协同机制的领队流转、协作痕迹机制的权重衰减 / 降权恢复。
3. **稳定支撑第三方 API 与本机 CLI 编排**：连接池、重试、限流、熔断、流式转发、本机执行网关沙箱。
4. **私有化交付友好**：一键 Compose 起环境；不依赖公网服务；密钥集中管理；数据可备份可迁移。

### 1.2 非目标（本方案范围外，标注去向）

- 公有云多租户 SaaS 化 → R3 抽象扩展点
- 一键部署到公有云 / Helm chart → R2
- 移动端 / 客户端 SDK → 待定
- Agent 之间跨机推理调度 → 待定（当前所有 Agent 都是"某个 API 提供方的模型 + 我方编排"）

## 2. 技术选型论证

### 2.1 全栈 Node.js + TypeScript

| 论据 | 具体 |
|---|---|
| 与现有原型无缝对接 | 原型是原生 HTML+JS，Next.js 迁入零心智损耗；设计令牌 / 交互直接复用 |
| 场景吻合 | 平台负载以"调第三方 API + 编排本机 CLI"为主，纯 I/O 密集，Node event loop 强项 |
| 类型系统跨端一致 | `packages/shared` 里定义的 DTO / 契约前后端共享，杜绝 API 契约漂移 |
| AI SDK 生态 | `@anthropic-ai/sdk`、`openai`、`ai-sdk`、`langchain` 官方 Node 版第一梯队 |
| 招聘友好 | 中高级 TS/Node 供给充足；比 Go / Rust 团队搭建快 |

**已知短板与规避**：Node 单线程遇 CPU 重活会阻塞事件循环。RAG 索引 / embedding 计算 / 大文档解析 → 拆到独立 Python 微服务（不在 R1 范围，接口预留 §4.4）；`worker_threads` 兜底做中量 CPU 任务。

### 2.2 NestJS（Fastify adapter）

- 模块化 + DI + 装饰器风格，与企业级 Spring/Java 经验最平滑对接。
- Fastify adapter 相比默认 Express，QPS 高 40%+、更省内存。
- 官方生态齐全：ValidationPipe、Guard、Interceptor、Swagger、OpenTelemetry 中间件。
- 与 BullMQ、Prisma、Redis、SSE 集成成熟。

### 2.3 Next.js 14 App Router

- 承接现有 `prototype/index.html` 交互；同一份设计令牌迁进 CSS Modules / Tailwind。
- Server Component + Route Handler，一部分只读页面可 SSR 直接从后端拉数据（降 JS 体积）。
- 生产可导出为静态资产 + BFF 分离部署，便于私有化裁剪。

### 2.4 数据平面

| 组件 | 选型 | 理由 |
|---|---|---|
| 关系库 | **PostgreSQL 16** | JSONB + 强类型 + 全文搜索 + LISTEN/NOTIFY，一库满足业务 + 半结构化 |
| ORM | **Prisma** | schema 即真源、迁移工具成熟、类型自动生成 |
| 缓存 / 队列 / pub-sub | **Redis 7** | BullMQ 依赖，同时承担认领意愿实时累积、协作痕迹权重缓存、SSE 频道 |
| 对象存储 | 私有化：MinIO；SaaS 化：S3 兼容 | 文档 / 素材落地 |
| 全文检索 | R1 用 PG 内置 `pg_trgm` + tsvector，R2 视需要引入 Meili/OpenSearch | 避免过早引入 ES |

### 2.5 观测与运维

- **OpenTelemetry**：Traces + Metrics 双通道，SDK 一次配置多后端。
- **日志**：结构化 JSON（Pino），生产走 Loki，本地 stdout。
- **指标**：Prometheus scrape；关键 SLI（Agent 认领 P95、评审待处理时长、外部 API 错误率 / 熔断触发次数）。
- **部署**：R1 Docker Compose（本地 + 单节点私有化）；R2 Helm chart（K8s 多副本）。

## 4. 模块拆分（bounded contexts）

按业务边界切分，每个模块自己拥有 controller / service / repository，跨模块只通过明确定义的接口 / 事件通信（不直接跨 repository）。

### 4.1 identity（身份 / RBAC / 审计）
- 用户、角色、权限、组织；JWT + 短期 refresh。
- 所有写操作过审计拦截器，落 `audit_log` 表（谁 / 何时 / 何操作 / 前后快照）。

### 4.2 agents
- Agent 档案 CRUD、技能标签、可挂载 Skill 模块（builtin / local / market）、协作偏好、权限（confirmCode / confirmExternal / budget）。
- `trace_delta` 与 `recent_rejects` 由 collaboration 模块回写。

### 4.2b teams（团队 · 与自主认领并列的第二种组织方式）
- 团队 CRUD：一组 Agent + 一位 owner。
- 任务发布可选团队模式：`Task.assignMode = 'team'` + `teamId` + `teamOwnerAgentId`。
- 只有团队负责人（用户身份或代理其调用）能给团队内步骤指派人；全部完成后由负责人显式调用 `POST /api/tasks/:id/team/submit-review` 推入 `review`。
- **评审红线不放开**：团队负责人无 review 权限，`review → done` 仍只能由 reviewer 人工用户走 review 模块。

### 4.3 tasks
- 任务发布 / 状态机 / 步骤计划 / 参与人；分配方式三选一（`auto` / `manual` / `team`）。
- 状态：`open → planning → progress → review → done`（不可跳过 review 直接 done——**评审红线代码强约束**，见 §7 与 §8）。

### 4.4 collaboration（协作痕迹机制的载体）
- 协作时间线事件（append-only）、临时领队推断（`plan.find(s => s.status==='active').agentId`）、卡点组队 / 解散。
- **协作痕迹**：任务完成后异步更新对应 Agent 的 `trace_delta`（近期同类任务频次）+ 衰减调度（BullMQ cron）。
- 事件通过 Redis pub-sub 广播给 SSE 通道。

### 4.5 review（评审红线独立模块）
- 只暴露两个接口：`POST /docs/:id/approve`、`POST /docs/:id/reject`。
- **只接受人工用户调用**（Guard 拒绝系统身份 / Agent token）；**tasks 模块无 review 权限**——从架构上杜绝"系统自动通过评审"。
- 详见 §8。

### 4.6 providers（AI 模型接入）
- API 提供方 CRUD、测试连接、模型发现；密钥用 AES-256-GCM 加密落库（密钥主密钥由 KMS / env 提供）。
- `availableModels()` 派生视图：只返回"启用 + 已连接"提供方的模型，供 agents 选择时用。

### 4.7 execution（外部 API + 本机 CLI 执行网关）
- 统一 `Executor` 抽象；两种实现：
  - `HttpApiExecutor`：`undici` + 连接池 + 限流 + 熔断 + 流式转发（LLM SSE 中转）
  - `LocalCliExecutor`：`child_process.spawn` + 白名单 + 沙箱 + 超时 + 并发信号量
- 详见 §9。

### 4.8 docs
- Agent 产出物存储、类型化、引用统计（`被引用 N 次` = 出现在多少条 collaboration 事件里）。
- 二进制内容走对象存储，元数据落 PG。

### 4.9 notifications
- SSE 通道：`GET /api/stream/tasks/:id` 订阅某任务的时间线增量。
- Redis pub-sub 内部路由 → 单 API 进程可服务多任务订阅者；多副本部署下每副本各持自己订阅集合。

## 5. 数据模型（Prisma schema · 核心表）

以下为 R1 必需的最小闭环。字段命名紧扣原型 `AGENTS` / `TASKS` / `DOCS` / `PROVIDERS`，一一映射。

```prisma
// prisma/schema.prisma 节选

model User {
  id           String   @id @default(cuid())
  email        String   @unique
  passwordHash String
  roles        Json     // ["admin","reviewer","operator"]
  createdAt    DateTime @default(now())
}

model Agent {
  id           String   @id @default(cuid())
  name         String
  avatar       String
  role         String
  status       AgentStatus @default(idle)
  bio          String   @db.Text
  skills       String[]
  modules      String[] // MODULE_CATALOG key
  collabPref   CollabPref @default(auto)
  modelKey     String?  // -> Provider.models[].id
  effort       Effort   @default(medium)
  permissions  Json     // { confirmCode, confirmExternal, budget }
  traceDelta   Int      @default(0)   // 协作痕迹机制的权重
  traceLabel   String?
  recentRejects Int     @default(0)   // 降权触发计数
  stats        Json     // { tasksDone, avgScore, collabs }
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
  @@index([status])
}

enum CollabPref  { auto manual }
enum Effort      { low medium high }

model Task {
  id                String   @id @default(cuid())

  description       String   @db.Text
  status            TaskStatus @default(open)
  priority          Priority   @default(mid)
  requiredSkills    String[]
  assignees         String[]           // Agent.id[]
  progressPct       Int      @default(0)

  agentId       String
  preview       String   @db.Text

model Provider {
  id          String  @id @default(cuid())

  type        ProviderType
  baseUrl     String
  apiKeyEnc   Bytes    // AES-256-GCM 密文
  apiKeyIv    Bytes
  apiKeyTag   Bytes
  apiKeyLast4 String   // 界面脱敏展示用
  enabled     Boolean  @default(true)

model AuditLog {
```

## 7. 三层机制的后端落地

### 7.1 自主认领机制（意愿累积 + 契约匹配）

- 意愿分实时计算：`baseScore(技能契约命中率) + traceDelta(近期同类任务频次 boost / 久未接触 decay) - rejectDelta(降权)`。
- 未认领任务的紧急度 = 累积函数 `f(openHours)`，前端拿 `openHours` 自己插值出强度条；服务端仅存原值。
- 排序：`pinned ASC → openHours DESC`——**人工置顶永远盖过算法**（写死在 sort，不做成配置项）。

**核心算法**（伪代码，实际实现见 `tasks.service.ts`）：

```ts
function computeIntent(task: Task, agent: Agent) {
  const matched = task.requiredSkills.filter(s => agent.skills.some(a => a.includes(s) || s.includes(a)));
  const base = Math.round(matched.length / task.requiredSkills.length * 100);
  const trace = agent.traceDelta;
  const downweight = agent.recentRejects >= REJECT_DOWNWEIGHT_THRESHOLD ? -8 : 0;
  return { score: clamp(base + trace + downweight, 0, 99), matched, base, trace, downweight };
}
```

### 7.2 临时协同机制（领队流转 + 攻坚小组）

- 领队 = `plan.find(s => s.status === 'active').agentId`——**推断值，不落库**，避免与 plan 状态漂移。
- 换人接棒：修改 `step.agentId`；把新 agent 加入 `task.assignees`（去重）；发一条 `system` 事件。
- 卡点组队：`step.blocked = true`；`step.squad = [原 agent, 高战绩空闲 agent]`；解除时置 `blocked=false`、`squad=[原 agent]`；全程写事件。

### 7.3 协作痕迹机制（权重衰减 + 降权恢复）

- **累积**：任务 done 时，参与人 `traceDelta += +2`，`traceLabel = "近期同类任务完成频繁"`（同类判定按技能重叠）。
- **衰减**：每日 cron（BullMQ repeatable job）对所有 Agent `traceDelta = round(traceDelta * 0.9)`，绝对值 <1 归零并清空 label。
- **降权**：文档被打回时 `recent_rejects += 1`；达到阈值即在意愿分里生效 `-8`。
- **恢复**：文档被批准时 `recent_rejects = max(0, recent_rejects - 1)`。**只有人工批准能触发恢复**（review 模块独占入口）。

## 8. 评审红线的强约束（不可绕过）

**问题**：红线仅靠文档约定容易失守。方案上用**代码 + 权限 + 审计**三层强制：

### 8.1 权限层：Guard 拒绝非人工调用

```ts
// review.guard.ts
canActivate(ctx) {
  const req = ctx.switchToHttp().getRequest();
  if (req.actor.type !== 'user') throw new ForbiddenException('review action requires human user');
  return true;
}
```

**Agent token / System token 打到 review 接口即 403。**

### 8.2 领域层：状态机拒绝跳过 review

```ts
// tasks.service.ts
private validateTransition(from: TaskStatus, to: TaskStatus) {
  const allowed = { open:['planning'], planning:['progress'], progress:['review'], review:['done'], done:[] };
  if (!allowed[from].includes(to)) throw new BadRequestException(`illegal transition ${from} -> ${to}`);
}
// tasks 模块内部无 `review -> done` 触发路径；done 只在 review.service.approveAllDocs() 里发起
```

### 8.3 审计层：每一次批准 / 打回强制落审计

`review.service` 的 approve/reject 走 `@Audit()` 拦截器，`AuditLog.action = 'review.approve' | 'review.reject'`，`actor` 必须是 `user`。任何绕过路径审计里都会缺一条对应记录 → CI 端加断言（"review.approve 数量 == done 状态任务数"）。

## 9. 外部 API 与本机 CLI 的可靠调用

### 9.1 HttpApiExecutor（第三方 API 中转 / LLM 流式转发）

- HTTP 客户端：`undici`（原生更快、支持 keep-alive 连接池 / HTTP/2）。
- **连接池**：每个 Provider 一个 `Pool`，pipelining 2、connections 32；避免 head-of-line 阻塞。
- **限流**：令牌桶（`bottleneck`），按 Provider 的 RPM / TPM 限额配置。
- **重试**：指数退避 + jitter，仅对 429 / 5xx / 网络错；4xx（非 429）不重试。
- **熔断**：`opossum`，触发条件 = 30 秒内错误率 > 50% 且请求数 > 20；半开态每 30 秒放一次探针。
- **流式转发**：LLM SSE 从上游 Response body 直连管道到我方 SSE 响应，中间不缓冲，`ReadableStream.pipeThrough` 加 backpressure。

### 9.2 LocalCliExecutor（本机 CLI 网关）

- **白名单**：CLI 命令 + 允许参数模式（正则）在 `cli-whitelist.yaml` 声明，未在名单里直接拒绝。
- **沙箱**：CWD 强制到指定目录；env 白名单；`shell:false`（禁 shell 注入）；`stdin` 关闭除非声明允许。
- **超时 / 内存上限**：每次调用带 `timeoutMs` 与 rlimit（Linux 上通过 `prlimit` 包装，或用 `child_process` + `setTimeout(kill)` 退化实现）。
- **并发信号量**：全局 `p-limit(N)`，防止一次 spawn 几百个进程打死机器。
- **流式输出**：stdout 直接管道到调用方 SSE / WS；stderr 单独通道；不在 Node 主进程里 `JSON.parse` 大 body。
- **安全边界**：LocalCliExecutor 部署为**独立进程**（可作为独立 systemd unit / K8s DaemonSet），主 API 通过 Unix domain socket 或 gRPC 调用；主 API 本身不 `spawn`——避免"主服务被溢出的子进程拖死"的连坐风险。

## 10. 安全

### 10.1 密钥管理

- API Key 落库前用 AES-256-GCM 加密（`apiKeyEnc/Iv/Tag`）；主密钥从环境变量（本地）或 KMS / Vault（生产）取。
- 界面永远脱敏（`sk-****last4`）；查询接口不返回明文，只在**外发上游 API 时**在内存解密。
- 日志 / 审计里对 Authorization 头 / apiKey 字段做正则脱敏（Pino serializer）。

### 10.2 RBAC

R1 角色：`admin` / `reviewer` / `operator` / `viewer`；Guard 装饰器 `@Roles('reviewer')` 声明。**评审接口在 Guard 层与角色层双重校验（`user` + `reviewer`）**。

### 10.3 审计

所有写操作（含 review）过 `AuditInterceptor`，落 `audit_log`；关键操作（review、provider 增删、agent 删除、任务发布）额外冗余落日志到 Loki 便于查询。
