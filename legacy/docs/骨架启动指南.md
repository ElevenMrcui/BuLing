# 不令 · 企业级骨架启动指南

> 配套 [`企业级架构与落地方案.md`](企业级架构与落地方案.md) 的 R1 最小可跑骨架启动步骤。三分钟内跑通"发布任务 → 自主认领 → 完成步骤 → 人工评审"完整链路。

---

## 0. 先决条件

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | **≥ 22.15.0** | LTS；`nvm install 22 && nvm use 22` |
| pnpm | **≥ 9.0** | `corepack enable && corepack prepare pnpm@9.12.0 --activate` |
| Docker | 现代版本 | 起本地 Postgres + Redis |
| Make | 任意 | 命令入口简化用；不用 make 也可直接看 Makefile 里的 pnpm/docker 命令 |

---

## 1. 首次启动（3 分钟）

```bash
# 1) 环境变量
cp .env.example .env

# 2) 安装依赖
make install                    # === pnpm install

# 3) 起本地依赖（Postgres + Redis）
make db                         # docker compose up -d

# 4) 生成 Prisma Client + 首次迁移 + 种子数据
make generate
make migrate                    # 会创建 apps/api/prisma/migrations
pnpm --filter @buling/api prisma:seed

# 5) 起 API + Web（并行）
make dev
# API  http://localhost:13500/api/health
# Web  http://localhost:13000
```

首次 `migrate` 时 Prisma 会问你迁移名称，随便起（例如 `init`）。

## 2. 端到端流程演示

浏览器打开 **http://localhost:13000/tasks**：

1. **发布任务**：填标题 → 点"发布"，看到卡片进入"open"状态。
2. **自主认领**：种子里的 `t-open-1` 也可直接从下拉里选一个 Agent 认领；状态自动进入 `planning`，plan 步骤生成。
3. **完成步骤**：点"查看协作详情" → 依次"标记完成"，最后一步完成后自动转 `review`。
4. **人工评审（红线）**：种子里已放 `t-review-1` + `d-security-1`（待评审文档），进入该任务详情：
   - 点 **批准**：Web 客户端带 `x-actor-type=user, x-actor-roles=reviewer`，服务端放行，doc `approved`，任务转 `done`。
   - 点 **打回**：Agent `明镜` 的 `recentRejects+1`；到阈值 2 就触发临时降权。
   - **想试红线拦截**？改 `apps/web/lib/api.ts` 里 review 部分的 `roles` 字段（去掉 `reviewer` 或改 `type=agent`），会看到 403 "评审红线由此拦截"。

## 3. 直接打后端 API（不经 Web）

```bash
# 健康检查
curl -s http://localhost:13500/api/health

# 列表任务
curl -s http://localhost:13500/api/tasks

# 认领
curl -s -X POST http://localhost:13500/api/tasks/t-open-1/claim \
  -H 'content-type: application/json' \
  -H 'x-actor-type: user' -H 'x-actor-id: u-demo' -H 'x-actor-roles: operator' \
  -d '{"agentId":"guanhai"}'

# 评审红线：用 agent 身份打评审接口 → 403
curl -i -X POST http://localhost:13500/api/review/docs/d-security-1/approve \
  -H 'x-actor-type: agent' -H 'x-actor-id: guanhai'

# 评审红线：用 user 但缺 reviewer 角色 → 403
curl -i -X POST http://localhost:13500/api/review/docs/d-security-1/approve \
  -H 'x-actor-type: user' -H 'x-actor-id: u-demo' -H 'x-actor-roles: operator'

# 评审红线：user + reviewer → 200
curl -i -X POST http://localhost:13500/api/review/docs/d-security-1/approve \
  -H 'x-actor-type: user' -H 'x-actor-id: u-reviewer' -H 'x-actor-roles: reviewer'
```

## 5. 目录结构（骨架）

```
apps/
  api/                  NestJS + Fastify + Prisma
    prisma/
      schema.prisma     数据模型（PG）
      seed.ts           种子：Agent × 6、任务 × 2、Provider × 1、reviewer × 1
    src/
      main.ts
      app.module.ts
      health.controller.ts
      common/
        actor.ts        ActorGuard + AllowedActors 装饰器（评审红线拦截点 #1）
        prisma.service.ts / prisma.module.ts
        logger.ts       Pino 结构化日志 + redact 白名单
      modules/
        tasks/          任务：CRUD + 意愿分 + 状态机（禁跳过 review）
        agents/         Agent 只读
        review/         评审红线独立模块（唯一能把任务转 done 的入口）
        providers/      模型接入 + AES-256-GCM 密钥加密
  web/                  Next.js 14 App Router
    app/tasks/          E2E 演示页
    lib/api.ts          客户端 SDK（带 actor 头）
packages/
  shared/               前后端契约唯一真源（DTO / 枚举 / 常量）
infra/
  docker-compose.yml    Postgres + Redis
prototype/index.html    高保真交互原型（R2 迁入 Web 完整体验）
docs/                   项目文档
```

## 6. 已实现 vs TODO

**R1 已实现**：
- 五模块骨架（tasks / agents / review / providers）+ Prisma schema + 种子数据
- 评审红线的三层强约束（Guard + 状态机 + 审计记录）
- 意愿分算法（协作痕迹权重 + 降权阈值）+ 状态机（不可跳过 review）
- Provider API Key AES-256-GCM 加密落库 + 界面脱敏 + 演示态测试连接
- 结构化日志 + 密钥字段自动 redact

- BullMQ 队列 + Redis pub-sub + SSE 协作时间线实时推送

- HttpApiExecutor（undici 池 + bottleneck 限流 + opossum 熔断 + LLM 流式转发）
- 真实 JWT 认证 + refresh
- Web 迁入 prototype 完整 UI 与设计令牌
- Helm chart · GitHub Actions CI
