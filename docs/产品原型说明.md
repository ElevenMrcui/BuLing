# 不令 · 产品原型说明

> 本文是 `prototype/index.html` 的规格说明：覆盖页面、数据模型、关键交互，以及"哪些是真交互 / 哪些是 mock"的边界。改动原型前先读对应段；改完回填本文。

---

## 1. 技术形态

- **单文件、零依赖、免构建**：HTML + 内联 CSS + 原生 JavaScript，全部在 `prototype/index.html` 里。无框架、无打包、无后端。
- **主题**：深 / 浅色三态（显式 light / 显式 dark / 跟随系统），设计令牌驱动；主题选择存 `localStorage`（键 `buling-theme`）。
- **响应式**：桌面侧边栏常驻；窄屏折叠为抽屉导航。
- **状态**：全部内存态。刷新页面即回到初始种子数据——**没有持久化，没有网络请求**。

---

## 2. 全局布局

- **侧边栏**：品牌区（"不令 · 其身正，不令而行"）→ "协作机制说明"入口 → 五个导航项 → 用户信息 + 主题切换。
- **顶栏**：当前页面标题 + 副标题 + 全局搜索（回车跳转到命中的任务详情 / Agent 抽屉 / 文档预览）。
- **五个页面**：工作台概览 / Agent 中心 / 任务 / 发布任务 / 文档产出库。

---

## 3. 页面逐个说明

### 3.1 工作台概览（`renderOverview` → `renderDashboardSummary` / `renderTaskDetail`）

一个 tab 承载两态：

- **默认态：状态摘要**——四张统计卡（Agent 总数 / 进行中任务 / 待评审产出 / 本周完成）+ "最近动态"时间线 + "Agent 状态"列表。
- **详情态：协作详情**——点击任意"最近动态"条目或从别处进入某个已认领任务时，原地切换为该任务的协作详情，同屏展示：
  - **自动任务规划**：步骤流水线；当前活跃步骤上标"临时领队"；每步可"标记为完成"、"换人接棒"、"标记为卡点"（触发临时攻坚小组）/"解除攻坚小组"。
  - **协作时间线**：系统事件 + 各 Agent 发言 + 产出文档引用。
  - **产出文档**：任务处于"待评审"时，未批准文档就地露出"打回 / 批准"按钮；已批准的显示"已批准"徽章。
  - **协作团队**：参与该任务的 Agent 名单。
  - 顶部"返回工作台概览"回到摘要态。

### 3.2 Agent 中心（`renderAgents`）

- **"创建新 Agent"卡片置顶**（网格第一位，优先级最高）。
- 其余为 Agent 卡片：头像 / 名称 / 角色 / 状态 / 简介 / 技能 / 战绩（完成数 / 评分 / 协作次数）；近期多次被打回的 Agent 显示"匹配权重临时下调"标签。
- 点卡片进入**五步创建 / 编辑向导**（见 §5）。

### 3.3 任务（`renderTasks`）

- **纯任务看板**，五列：待认领 / 规划中 / 执行中 / 待评审 / 已完成。
- 顶部"发布任务"按钮（也可从侧边栏"发布任务"进入）。
- **待认领卡**：紧急度累积条（未认领时长越长越显眼）+ 人工置顶按钮 + 认领意愿（把最高意愿的强度烤进横幅底色）+ 展开候选人 + "自动匹配领取"/"自动组队认领"。
- 点已认领的卡 → 跳到"工作台概览"看协作详情。

### 3.4 发布任务（`renderPublishTask`）

- **独立表单页**（不是弹窗）：任务标题 / 描述 / 所需技能（回车加标签）/ 优先级（高 / 中 / 低）/ 截止时间 / 分配方式（自动匹配领取 vs 指定 Agent）。
- 发布后写入 `TASKS` 并跳到任务看板。

### 3.5 文档产出库（`renderDocs`）

- 两种视图：**按项目分组**（默认，按任务归集，未归属的单列"未归类"）/ **全部文档（可按类型筛选）**。
- 文档卡显示类型 / 标题 / 来源任务 / 作者 / 日期；被协作记录引用过的显示"被引用 N 次"。
- 点开为预览弹窗（内容预览 + 来源任务跳转 + 导出——导出为演示态，不产生真实文件）。

## 4. 数据模型（内存态 mock）

### 4.1 Agent（`AGENTS[]`）

| 字段 | 说明 |
|---|---|
| `id` / `name` / `avatar` / `role` | 身份 |
| `status` | `working` / `idle` / `offline` |
| `bio` | 人格设定 / 系统提示词前缀 |
| `skills[]` | 技能标签（用于任务契约匹配） |
| `modules[]` | 已挂载的 Skill 模块 key（指向 `MODULE_CATALOG`） |
| `collabPref` | `auto`（自动认领）/ `manual`（仅指定分配） |
| `model` | `haiku` / `sonnet` / `opus`（见 `MODEL_META`） |
| `effort` | `low` / `medium` / `high`（推理强度，见 `EFFORT_META`） |
| `permissions` | `{ confirmCode, confirmExternal, budget }`——执行代码 / 对外发送前是否需人工确认、单任务预算上限 |
| `stats` | `{ tasksDone, avgScore, collabs }` 战绩 |
| `trace` | 协作痕迹权重：`{ delta, label }`——近期做过同类任务为正（boost），久未接触为负（decay） |
| `recentRejects` | 近期被打回次数；≥ `REJECT_DOWNWEIGHT_THRESHOLD`（默认 2）时临时降权 |

### 4.2 Task（`TASKS[]`）

| 字段 | 说明 |
|---|---|
| `id` / `title` / `desc` | 基本信息 |
| `status` | `open` / `planning` / `progress` / `review` / `done`（见 `STATUS_META`） |
| `priority` | `high` / `mid` / `low`（见 `PRIORITY_META`）——仅在已认领后展示；待认领用紧急度条替代 |
| `requiredSkills[]` | 所需技能（契约匹配依据） |
| `assignees[]` | 参与 Agent id |
| `plan[]` | 步骤：`{ title, status, agentId, squad?, blocked?, light? }`；`light:true` = 轻量执行单元（无固定身份，用完即释放） |
| `logs[]` | 协作时间线：系统事件 / Agent 发言 / typing 态，可带 `doc` 引用 |
| `docs[]` | 产出文档 id |
| `progressPct` | 整体进度 |
| `openHours` / `pinned` | 未认领时长 / 人工置顶 |

### 4.3 Doc（`DOCS[]`）

`{ id, title, type, taskId, agentId, date, preview, reviewStatus? }`。`type` ∈ `doc` / `pdf` / `sheet` / `image`；`reviewStatus:'approved'` 由人工批准置入。

### 4.4 Skill 模块

- `MODULE_CATALOG`：已安装模块字典，条目形状 `{ name, icon, desc, permission, origin, publisher? }`。`origin` ∈ `builtin`（预置）/ `local`（本机）/ `market`（市场）——**"来源"只是溯源标签，不代表特权，所有已安装条目一律可删除**。
- `LOCAL_CANDIDATES`：本机网关"扫描"后的候选能力（**模拟数据**）。
- `MARKET_CATALOG`：技能市场中未安装条目。

## 5. Agent 创建 / 编辑向导（五步）

`openAgentDrawer` → `agentWizardHtml` → `wireAgentWizardEvents`（事件委托绑在 `modal-container`，换步骤只换 innerHTML）：

1. **身份**：头像 / 名称 / 角色定位（名称为唯一必填）。
2. **人格与模型**：系统提示词 / 底层模型（Haiku / Sonnet / Opus）/ 推理强度（低 / 中 / 高）。
3. **技能与模块**：技能标签 + 可挂载 Skill 模块面板，三个来源 tab：
   - **已安装**：所有 `MODULE_CATALOG` 条目，可开关、可删除（删除会从所有 Agent 上一并移除挂载）。
   - **本机发现**：需先"扫描本机"（模拟）；发现的候选默认全关，逐项授权。
   - **技能市场**：浏览可安装条目 + "按链接安装" + "上传技能包"（均为演示态，安装后并入"已安装"）。
4. **协作与权限**：协作偏好（自动认领 / 仅指定）+ 需人工确认的边界（执行代码前 / 对外发送前）+ 单任务预算上限。
5. **确认**：汇总前四步，创建 / 保存。

---

## 6. mock 边界（重要）

原型里所有"看似有后端"的行为都是内存态演示，改动时**必须保持这条边界，不要在原型里接真实能力**：

- **本机发现 / 扫描本机**：不真的访问用户本机进程或 CLI 列表——浏览器沙箱里的网页天然拿不到。候选列表是"接上真实本机网关后大致会长什么样"的示意。
- **上传技能包 / 按链接安装**：不真的抓取或执行任何外部代码，只是把一条"未验证 · 来自你本人 / 外部链接"的记录加入已安装列表。
- **导出文档**：只弹提示，不产生真实文件。
- **一切数据**：刷新即回初始种子，无持久化、无网络。

## 7. 与机制设计的关系

原型里的动态交互（认领意愿累积、痕迹权重 boost/decay、临时领队流转、卡点组队、被打回降权与恢复、评审红线）是 [`协作机制设计.md`](协作机制设计.md) 中机制矩阵的**具体落地演示**。改这些交互前，务必先读机制设计核对不变量——尤其**评审红线不可自动化**。
