# 不令 · 产品原型说明

> 本文是 `prototype/index.html` 的规格说明：覆盖页面、数据模型、关键交互，以及"哪些是真交互 / 哪些是 mock"的边界。改动原型前先读对应段；改完回填本文。

---

## 1. 技术形态

- **单文件、零依赖、免构建**：HTML + 内联 CSS + 原生 JavaScript，全部在 `prototype/index.html` 里。无框架、无打包、无后端。
- **主题**：深 / 浅色三态（显式 light / 显式 dark / 跟随系统），设计令牌驱动；主题选择存 `localStorage`（键 `buling-theme`）。
- **响应式**：桌面侧边栏常驻；窄屏折叠为抽屉导航。
- **状态**：全部内存态。刷新页面即回到初始种子数据——**没有持久化，没有网络请求**。

---

## 2. 全局布局

- **侧边栏**：品牌区（"不令 · 其身正，不令而行"）→ "协作机制说明"入口 → 五个导航项 → 用户信息 + 主题切换。
- **顶栏**：当前页面标题 + 副标题 + 全局搜索（回车跳转到命中的任务详情 / Agent 抽屉 / 文档预览）。
- **导航分两组**：
  - 工作区：工作台概览 / Agent 中心 / **团队** / 任务 / 发布任务 / 文档产出库
  - 配置：模型接入

---

## 3. 页面逐个说明

### 3.1 工作台概览（`renderOverview` → `renderDashboardSummary` / `renderTaskDetail`）

一个 tab 承载两态：

- **默认态：状态摘要**——四张统计卡（Agent 总数 / 进行中任务 / 待评审产出 / 本周完成）+ "最近动态"时间线 + "Agent 状态"列表。
- **详情态：协作详情**——点击任意"最近动态"条目或从别处进入某个已认领任务时，原地切换为该任务的协作详情，同屏展示：
  - **团队模式条**：任务处于团队模式时（`assignMode:'team'`），顶部展示紫色横幅——团队名 · 负责人 · 成员头像 chips，并明示"评审仍走人工红线，不因此绕过"。
  - **任务规划**：步骤流水线；当前活跃步骤上标"临时领队"（团队模式下恒定 = 团队负责人）；每步可"标记为完成"、"换人接棒"、"标记为卡点"（触发临时攻坚小组）/"解除攻坚小组"；**团队模式下未指派 / 未激活的步骤加"团队负责人指派"下拉**（只列该团队的成员）；**团队模式下全部步骤完成后加"汇总并提交评审"按钮**（把任务推入 `review`）。
  - **协作时间线**：系统事件 + 各 Agent 发言 + 产出文档引用。
  - **产出文档**：任务处于"待评审"时，未批准文档就地露出"打回 / 批准"按钮；已批准的显示"已批准"徽章。
  - **协作团队**：参与该任务的 Agent 名单。
  - 顶部"返回工作台概览"回到摘要态。

### 3.2 Agent 中心（`renderAgents`）

- **"创建新 Agent"卡片置顶**（网格第一位，优先级最高）。
- 其余为 Agent 卡片：头像 / 名称 / 角色 / 状态 / 简介 / 技能 / 战绩（完成数 / 评分 / 协作次数）；近期多次被打回的 Agent 显示"匹配权重临时下调"标签。
- 点卡片进入**五步创建 / 编辑向导**（见 §5）。

### 3.2b 团队（`renderTeams` + `openTeamDrawer`）

与自主认领并列的第二种任务组织方式（详见 [`协作机制设计.md § 1.1`](协作机制设计.md#11-团队模式与自主认领并列的第二种任务组织方式)）。

- **团队列表**：卡片式，显示团队名 / 描述 / 负责人徽章 / 成员头像 chips；置顶一张"创建新团队"卡片。
- **创建 / 编辑团队**（modal）：团队名称 / 描述 / 团队负责人下拉（全体 Agent 中选一位）/ 团队成员多选（勾选框）。保存时若负责人未在成员里会自动补入；删除前会校验"该团队有无进行中的任务在使用"。

### 3.3 任务（`renderTasks`）

- **纯任务看板**，五列：待认领 / 规划中 / 执行中 / 待评审 / 已完成。
- 顶部"发布任务"按钮（也可从侧边栏"发布任务"进入）。
- **待认领卡**：紧急度累积条（未认领时长越长越显眼）+ 人工置顶按钮 + 认领意愿（把最高意愿的强度烤进横幅底色）+ 展开候选人 + "自动匹配领取"/"自动组队认领"。
- 点已认领的卡 → 跳到"工作台概览"看协作详情。

### 3.4 发布任务（`renderPublishTask`）

- **独立表单页**（不是弹窗）：任务标题 / 描述 / 所需技能（回车加标签）/ 优先级（高 / 中 / 低）/ 截止时间 / **分配方式（三选一：自动匹配领取 / 指定 Agent / 团队模式）**。
- 选择"团队模式"时展开团队 + 负责人下拉：选定团队后"负责人"下拉自动落到该团队的 owner，可改选团队内其他成员作为本任务的临时负责人。
- 发布后写入 `TASKS` 并跳到任务看板；团队模式的任务起始状态为 `planning`，plan 里已生成标准三步（"需求拆解与关键信息收集" 由负责人执行、"团队成员分工执行" 待负责人指派、"汇总与联合评审前自查" 由负责人执行）。

### 3.5 模型接入（`renderProviders`）

配置 Agent 可用的 AI API 模型来源（属"配置"分组）：

- **提供方卡片**：服务名称 + 类型徽章（Anthropic / OpenAI / OpenAI 兼容）+ 连接状态（已连接 / 未测试 / 连接失败）+ Base URL + API Key（**脱敏展示**）+ 该服务暴露的模型列表；每张卡可**启用 / 停用**开关、测试连接、编辑、删除。
- **"添加模型服务"**：弹窗表单——服务名称 / 服务类型 / Base URL / API Key → "测试连接并拉取模型"（按类型返回示意模型）→ 保存并接入。
- **与 Agent 的联动**：只有"**已启用 + 已连接**"的提供方，其模型才会出现在 Agent 创建向导第 2 步的"底层模型"选择里（按提供方分组）；停用 / 删除一个提供方会即时改变可选模型集合。

### 3.6 文档产出库（`renderDocs`）

- 两种视图：**按项目分组**（默认，按任务归集，未归属的单列"未归类"）/ **全部文档（可按类型筛选）**。
- 文档卡显示类型 / 标题 / 来源任务 / 作者 / 日期；被协作记录引用过的显示"被引用 N 次"。
- 点开为预览弹窗（内容预览 + 来源任务跳转 + 导出——导出为演示态，不产生真实文件）。

## 4. 数据模型（内存态 mock）

### 4.1 Agent（`AGENTS[]`）

| 字段 | 说明 |
|---|---|
| `id` / `name` / `avatar` / `role` | 身份 |
| `status` | `working` / `idle` / `offline` |
| `bio` | 人格设定 / 系统提示词前缀 |
| `skills[]` | 技能标签（用于任务契约匹配） |
| `modules[]` | 已挂载的 Skill 模块 key（指向 `MODULE_CATALOG`） |
| `collabPref` | `auto`（自动认领）/ `manual`（仅指定分配） |
| `model` | 模型 key，指向某个已接入提供方的模型（见 §4.5 模型接入）；用 `modelByKey(key)` 反查其标签与所属提供方 |
| `effort` | `low` / `medium` / `high`（推理强度，见 `EFFORT_META`） |
| `permissions` | `{ confirmCode, confirmExternal, budget }`——执行代码 / 对外发送前是否需人工确认、单任务预算上限 |
| `stats` | `{ tasksDone, avgScore, collabs }` 战绩 |
| `trace` | 协作痕迹权重：`{ delta, label }`——近期做过同类任务为正（boost），久未接触为负（decay） |
| `recentRejects` | 近期被打回次数；≥ `REJECT_DOWNWEIGHT_THRESHOLD`（默认 2）时临时降权 |

### 4.2 Task（`TASKS[]`）

| 字段 | 说明 |
|---|---|
| `id` / `title` / `desc` | 基本信息 |
| `status` | `open` / `planning` / `progress` / `review` / `done`（见 `STATUS_META`） |
| `priority` | `high` / `mid` / `low`（见 `PRIORITY_META`）——仅在已认领后展示；待认领用紧急度条替代 |
| `requiredSkills[]` | 所需技能（契约匹配依据） |
| `assignees[]` | 参与 Agent id |
| `plan[]` | 步骤：`{ title, status, agentId, squad?, blocked?, light? }`；`light:true` = 轻量执行单元（无固定身份，用完即释放） |
| `logs[]` | 协作时间线：系统事件 / Agent 发言 / typing 态，可带 `doc` 引用 |
| `docs[]` | 产出文档 id |
| `progressPct` | 整体进度 |
| `openHours` / `pinned` | 未认领时长 / 人工置顶 |
| `assignMode` | `auto` / `manual` / `team`（团队模式）；`open` 状态任务省略此字段视同 `auto` |
| `teamId` / `teamOwnerAgentId` | 团队模式下引用的团队 id 与该任务的团队负责人 Agent id |

### 4.3 Doc（`DOCS[]`）

`{ id, title, type, taskId, agentId, date, preview, reviewStatus? }`。`type` ∈ `doc` / `pdf` / `sheet` / `image`；`reviewStatus:'approved'` 由人工批准置入。

### 4.4 Skill 模块

- `MODULE_CATALOG`：已安装模块字典，条目形状 `{ name, icon, desc, permission, origin, publisher? }`。`origin` ∈ `builtin`（预置）/ `local`（本机）/ `market`（市场）——**"来源"只是溯源标签，不代表特权，所有已安装条目一律可删除**。
- `LOCAL_CANDIDATES`：本机网关"扫描"后的候选能力（**模拟数据**）。
- `MARKET_CATALOG`：技能市场中未安装条目。

### 4.4b 团队（`TEAMS[]`）

| 字段 | 说明 |
|---|---|
| `id` / `name` / `desc` | 团队标识 / 名称 / 一句话描述 |
| `ownerAgentId` | 默认团队负责人（Agent.id）；任务落到团队时可临时改选，但默认取此值 |
| `memberAgentIds[]` | 团队成员（Agent.id[]）；保存时若 owner 未在其中会自动补入 |

派生工具：`teamById(id)`。

### 4.5 模型接入 / API 提供方（`PROVIDERS[]`）

| 字段 | 说明 |
|---|---|
| `id` / `name` | 提供方标识 / 名称 |
| `type` | `anthropic` / `openai` / `compatible`（OpenAI 兼容，见 `PROVIDER_TYPE_META`） |
| `baseUrl` | API 端点 |
| `apiKeyMasked` | **脱敏后**的 API Key（原始 key 不落库，仅内存态，界面永不明文展示） |
| `enabled` | 是否启用 |
| `status` | `connected` / `untested` / `error`（见 `PROVIDER_STATUS_META`） |
| `models[]` | 该服务暴露的模型：`{ id, label, hint, ctx }` |

派生工具：`availableModels()` 展平所有"启用+已连接"提供方的模型（供 Agent 选择）；`modelByKey(key)` 反查某模型及其所属提供方。

## 5. Agent 创建 / 编辑向导（五步）

`openAgentDrawer` → `agentWizardHtml` → `wireAgentWizardEvents`（事件委托绑在 `modal-container`，换步骤只换 innerHTML）：

1. **身份**：头像 / 名称 / 角色定位（名称为唯一必填）。
2. **人格与模型**：系统提示词 / 底层模型 / 推理强度（低 / 中 / 高）。**底层模型从「模型接入」里已连接的提供方实时读取**，按提供方分组展示；无可用提供方时给出"前往模型接入"引导。
3. **技能与模块**：技能标签 + 可挂载 Skill 模块面板，三个来源 tab：
   - **已安装**：所有 `MODULE_CATALOG` 条目，可开关、可删除（删除会从所有 Agent 上一并移除挂载）。
   - **本机发现**：粘贴本地网关 Base URL + Token 完成配对，即刻扫描本机安装的 AI 厂商 CLI（Claude Code / Codex CLI / Gemini CLI / Ollama / Aider …）——**这一步不是模拟**，走真实 `http://127.0.0.1:17817/discover`（详见 [`docs/本地网关.md`](本地网关.md)）；未配对时列出示意与建议装法。发现结果默认全关，逐项开关授权挂载。
   - **技能市场**：浏览可安装条目 + "按链接安装" + "上传技能包"（均为演示态，安装后并入"已安装"）。
4. **协作与权限**：协作偏好（自动认领 / 仅指定）+ 需人工确认的边界（执行代码前 / 对外发送前）+ 单任务预算上限。
5. **确认**：汇总前四步，创建 / 保存。

## 6. mock 边界（重要）

原型里所有"看似有后端"的行为都是内存态演示，改动时**必须保持这条边界，不要在原型里接真实能力**：

- **本机发现 / 扫描本机**：**已接入真实本地网关**（`apps/local-gateway`，只监听 127.0.0.1、需 X-Gateway-Token）。未配对时展示的是"接上后大致会长什么样"的示意，配对后就是你本机的真实扫描结果。注意：网关只**发现**不**执行**，具体调用某个 CLI 的能力要落到未来的执行沙箱里。
- **上传技能包 / 按链接安装**：不真的抓取或执行任何外部代码，只是把一条"未验证 · 来自你本人 / 外部链接"的记录加入已安装列表。
- **导出文档**：只弹提示，不产生真实文件。
- **模型接入 / 测试连接**：不真的向任何 API 发起鉴权或模型列表请求；"测试连接"按服务类型返回一批**示意模型**。API Key 仅内存态、界面一律脱敏，**不落库、不外发**。接入真实后端后，这里才发起真实鉴权与拉取。
- **一切数据**：刷新即回初始种子，无持久化、无网络。

## 7. 与机制设计的关系

原型里的动态交互（认领意愿累积、痕迹权重 boost/decay、临时领队流转、卡点组队、被打回降权与恢复、评审红线）是 [`协作机制设计.md`](协作机制设计.md) 中机制矩阵的**具体落地演示**。改这些交互前，务必先读机制设计核对不变量——尤其**评审红线不可自动化**。
