## §1 你是谁 · 你在做什么

你是接手"不令"原型的开发 Agent。你的产出是让原型更接近产品意图，同时不破坏已经沉淀的交互与机制不变量。你**不是**在从零发明产品——产品主张、命名、三层协作机制、评审红线都已定稿（见 [`协作机制设计.md`](协作机制设计.md)），你的工作是在这个骨架内改进、扩展、修复。

不确定某个行为该怎样时，**默认不臆造**：查文档 → 查原型现有 mock 语义 → 仍不清楚就停下问用户。

## §2 硬约束（违背 = 返工）

1. **评审红线**：质量把关与评审必须由**人工显式打回 / 批准**，永不做成自动多数通过或规则自动放行。
2. **术语纪律**：界面文案与代码注释里**不出现蚁群 / 蜂群 / 狼群**，统一用功能名——**自主认领机制**、**临时协同机制**、**协作痕迹机制**。
3. **主题合规**：所有颜色走设计令牌（`var(--x)`）；**不得**把某个颜色的唯一定义放在 `@media prefers-color-scheme` 或 `[data-theme]` 块里；`body` 显式设背景令牌。否则深 / 浅色会串。
4. **不臆造**：技术栈、后端形态、业务规则（权限 / 计费 / 合规）未定的，标"待确认"交用户裁决。
5. **改动最小化**：紧扣需求，禁止"顺手改一下"无关代码。
6. **分支纪律**：只推 `claude/bulei-platform-prototype-dw7wxw`；未经许可不建 PR、不推别的分支。

**Pre-Dev checklist**（按顺序，不靠记忆）：

5. 确认优先级：**先保证既有交互自洽、不变量不破**，再谈新增。

## §4 设计先行

超过"单一自包含小改动"规模的工作，先设计后编码：

1. **背景** → [`产品原型说明.md`](产品原型说明.md)：要动的页面 / 数据模型现状。
2. **不变量** → [`协作机制设计.md`](协作机制设计.md)：你的改动必须符合的机制矩阵与红线。
3. **方案**：写清"改什么 / 为什么 / 影响哪些既有交互"（写在提交信息或一段 spec 里），再动手。
4. **回填**：完成后同步文档，让下个 agent 继承取舍。

碰到"自主认领 / 临时协同 / 协作痕迹 / 评审"四类机制时尤其要先想清楚——这些来自三轮讨论，改错代价大。

## §5 原型结构导览（怎么在单文件里定位）

`prototype/index.html` 是一个文件，内部按注释分段。改动时按段定位：

- **设计令牌**：文件头 `<style>` 里的 `:root` / `@media (prefers-color-scheme: dark)` / `:root[data-theme="dark"]` 三块，改配色先看这里有没有可复用变量。
- **组件样式**：按 `/* ===== 功能块 ===== */` 注释分隔（app-shell / 卡片 / 任务看板 / 任务详情 / 向导 / 机制矩阵 …）。
- **ICONS**：`const ICONS = {…}` 内联 SVG 表 + `{{ICON_*}}` 占位符替换。
- **数据模型（mock）**：`AGENTS` / `TASKS` / `DOCS` / `MODULE_CATALOG` / `LOCAL_CANDIDATES` / `MARKET_CATALOG` / `PROVIDERS`（AI API 提供方），全是内存态。
- **视图渲染**：`renderOverview`（=状态摘要+协作详情）/ `renderAgents` / `renderTasks`（看板）/ `renderPublishTask` / `renderProviders`（模型接入）/ `renderDocs` / `renderTaskDetail`。
- **状态**：`const State = {…}`（当前视图 / 打开的任务详情 / 各种筛选）。
- **交互装配**：`wireViewEvents()` 用事件委托绑定，切页面后重绑。Agent 创建向导用 `wireAgentWizardEvents()`，在 `modal-container` 上做事件委托（换步骤只换 innerHTML，不重绑，避免重复触发）。

各页面 / 数据字段的详细说明见 [`产品原型说明.md`](产品原型说明.md)。

## §6 编码规范

- 2 空格缩进、LF、UTF-8。
- JS 函数 `camelCase`，渲染函数统一 `render<View>`；数据属性 `data-<kebab>`；CSS 类 `kebab-case`，令牌 `--kebab`。
- 非显而易见的逻辑加**简洁中文注释**，说明"为什么"而非"做了什么"。
- 非原生可点元素接入 `makeKeyboardClickable`，保证 Tab / Enter/Space 可用与可见焦点态。
- 术语纪律见 §2.2。

## §7 测试（原型阶段 = 冒烟）

- 改动 `<script>` 后，先抽出脚本 `node --check` 确认无语法错误。
- 环境有 Playwright 时，无头 Chromium 加载页面，断言：无 JS 报错 + 五页可切换 + 关键流程可跑通（向导五步 / 任务认领 / 换人接棒 / 卡点组队与解散 / 文档评审批准联动 / 机制弹窗与流程图）。
- 自检问题：**"这次改动若让某页报错，冒烟会不会发现？"** 不会就补断言。
- 单元 / 集成 / 覆盖率阈值：待技术栈选定后定义（当前**待确认**）。

## §9 Commit

- Conventional Commits：`feat: …` / `fix: …` / `docs: …` / `refactor: …` / `chore: …`；原型 UI 改动用 `feat(prototype): …` / `fix(prototype): …`。
- 小步提交，一个可验证切片一个 commit，信息写清"改了什么、为什么"。
- 完成即推 `claude/bulei-platform-prototype-dw7wxw`；未经许可不建 PR。

## §10 常见陷阱

1. **主题串色**：颜色只写在 `@media` / `[data-theme]` 块里 → 未标记主题（系统默认态）下会用错色。永远先在 `:root` 定义完整调色板。
2. **向导事件重复触发**：把监听器绑在换 innerHTML 的节点上，换步骤后多绑一层 → 一次点击触发多次。装配一律绑在 `modal-container` 这类不被替换的外层，用事件委托。
3. **误把 mock 当真后端**：原型里"扫描本机 / 上传技能包 / 按链接安装 / 导出文档"都是演示态，不真的执行外部代码。改这些入口保持该边界。
4. **破坏评审红线**：给"待评审 → 已完成"加自动流转 = 违规。完成状态只能由人工批准全部产出触发。
5. **术语回流**：从旧素材粘代码时带回蚁群 / 蜂群 / 狼群字样。提交前全局搜一遍确认没有。
6. **顺手重构**：改 A 时"看不顺眼"顺手改 B。禁止；B 的问题单开一个 commit / 单独提。
